**기본 성질**
- `a ^ a = 0`, `a ^ 0 = a`
- 교환·결합법칙 성립 → 순서 상관없이 계산 가능
- `a ^ b = c` 이면 `a ^ c = b`, `b ^ c = a` (자기 자신이 역연산)
- 같은 값을 짝수 번 XOR하면 사라지고, 홀수 번이면 남음

**자주 쓰는 결론**
- 하나만 홀수 번 등장하는 수 찾기 → 전체 XOR
- 구간 XOR: `prefix[r] ^ prefix[l-1]`
- 0~n XOR은 `n % 4`로 O(1): 0→`n`, 1→`1`, 2→`n+1`, 3→`0`
- `|a - b| ≤ a ^ b ≤ a + b` (셋 다 홀짝 같음)
    - `c = a & b`, `x = a & ~b`, `y = ~a & b`이면
        - `c` : 둘 다 1, `x` : a만 1, `y` : b만 1 → 겹치는 비트 없음
        - `a = c + x`, `b = c + y`
        - `a - b = x - y`
        - `a ^ b = x + y`
        - `a + b = x + y + 2c`
    - `a + b = (a ^ b) + 2 * (a & b)` → XOR은 자리올림 없는 덧셈, 등호는 `(a & b) == 0`일 때
    - `a - b = (a ^ b) - 2 * (~a & b)` → XOR은 자리내림 없는 뺄셈, 등호는 `(a & b) == min(a, b)`일 때
- 비트별로 독립 → 각 비트의 1 개수 홀짝만 보면 됨
- 모든 쌍의 XOR 합: 비트별로 `(1의 개수) × (0의 개수) × 2^k`

**유형별 도구**
- 부분 배열 XOR이 k인 개수 → prefix XOR + 해시맵
- 최대 XOR 쌍 → 비트 트라이 (상위 비트부터 반대 비트 선택)
- 부분집합 XOR 최대/표현 가능 여부 → XOR 선형 기저 (가우스 소거)
- 님 게임 → 돌 개수 전체 XOR이 0이면 선공 패배, 일반 게임은 그런디 수 XOR
- 트리 경로 XOR → `d[u] ^ d[v]` (루트부터의 XOR, LCA 부분은 상쇄)
- 비트 뒤집기(토글) → `x ^ (1 << k)`, 0/1 전환은 `x ^ 1`

**주의**
- 연산자 우선순위가 비교 연산자보다 낮음 → `(a ^ b) == c`처럼 괄호 필수
- XOR 결과는 두 수의 최상위 비트 범위를 넘지 않음 (배열 크기 잡을 때 2의 거듭제곱 기준)
